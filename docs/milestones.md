# Milestones and decision gates

The [product brief](product-brief.md) sets scope and invariants; the [art rubric](art-direction.md) defines the visual gate. Task numbers refer to the dependency-linked children of Witan project `wp-pigment-prose-3e96a6` (parent epic `tk-pigment-prose-deliver-the-gpu-accelerated-landsc-0c782c`). This document is a roadmap, **not a claim that any feature or platform works**.

| Stage | Work | Exit evidence / gate |
| --- | --- | --- |
| 01 — Durable spec | Create the local repository, agree product/art rules, and check in synthetic passages. | Documents and ten fixtures reviewed; no backend or UI chosen. |
| 02 — Architecture experiment | Compare a fixed scenic painting pipeline with feasible alternatives; prototype candidate GPU rendering (Rust/wgpu is one candidate), paint layering and off-axis/tiled continuity on Linux RTX 4070. | Measured feasibility, license/dependency notes and a recorded backend choice or explicit unresolved risks; do not assume CPU fallback or Windows/macOS validation. |
| 03–04 — Core contracts | Define tested modules, text normalization, versioned recipes and independent seed streams. | Round-trip recipes, stream isolation and deterministic structural tests on the chosen implementation. |
| 05–07 — First visual prototype | Compose terrain and lake, then coherent color planes, watercolor washes, woods and rocks. | Multi-seed and variation contact sheet with settings and failed examples against the art rubric. |
| **08 — User visual gate** | Present multiple seeds and variants to the user, collect specific revision notes. | **Explicit user approval of visual quality** recorded before tasks 09–15; if rejected, iterate 05–07 and re-review. Automation cannot waive this gate. |
| 25 — Final-rendering detail | Wind, current and more ripples on water; less geometric, more complex rock surfaces (round 6 notes). Blocks 15. | User review in a numbered round; version bump and baseline refresh. |
| 09–15 — Linux MVP | Seamless bounded-memory tiled export; private versioned recipe persistence; non-blocking desktop preview; control wiring; progress/cancellation; regression/privacy/performance checks; Linux packaging and license audit. | Measured 4K/8K/custom, multi-aspect outputs without seams, recipe reload and privacy tests, plus actual Linux GPU validation. |
| 16–20 — Later landscapes | Biome-sensitive seasons, shared biome profiles, then distinct desert, tundra and jungle. | Coherent silhouettes/palettes across cycles, reviewed per-biome rather than generic recolors. |
| 21–22, 24 — Platform expansion | Validate/package Windows and macOS; full expanded-studio acceptance. | Evidence on actual supported GPU backends and packaging; no assumed cross-backend byte equality. |
| 23 — Separate study | Investigate CPU-only feasibility after core contracts. | Recorded go/no-go decision and performance/quality costs; no automatic MVP fallback. |

**Recorded outcomes.** 02 (2026-09-26): [architecture spike](architecture-spike.md). Rust + wgpu 30 compute painting over a 2.5D layered scene is recommended. Tiled output was bit-identical to single-image output up to 16K on the Linux RTX 4070 Ti (Vulkan). Direct3D 12 and Metal remain unverified. 03 (2026-09-26): [architecture and contracts](architecture.md), [ADR 0001](decisions/0001-renderer-and-desktop-shell.md). The stack is Rust 1.98 + wgpu 30.0.1 with an eframe/egui 0.36 shell. The Cargo workspace has `pigment-core` (portable contracts, 43 tests), `pigment-gpu` and `pigment-cli`. The GPU smoke path passes on the Linux RTX 4070 Ti and Intel iGPU (Vulkan) ([evidence](evidence/gpu-smoke-linux-2026-09-26.txt)). Portable CI is written but has not run yet. 04 (2026-09-26): [seeds and recipes](seeds-and-recipes.md). Text normalization `nfc-lf-utf8/1` (NFC, CRLF/CR → LF) and seed algorithm `pigment-seed/1` (domain-separated SHA-256 streams, xoshiro256\*\*) are frozen by 21 text vectors that an independent Python implementation reproduces. Recipe schema 1 has a strict loader: future schemas, unknown/missing keys, duplicate keys, wrong types and out-of-range values are rejected, and generator/renderer drift loads with a notice. `pigment-core` has 73 tests. Portable CI then passed on Linux, Windows and macOS, so the vectors hold on all three. 05 (2026-09-26): [scene generation](scene-generation.md). The lakeshore generator has three composition templates, fractal massifs with lit and shadowed facet planes, a far shore and lake, a near shore, woodland placement regions and faceted rocks. Every layer is a simple x-monotone band, and the generator uses exact arithmetic (frozen checksums). The GPU debug views match the CPU rasterizer on every pixel. Contact sheets for the corpus in landscape, portrait and square, variations, form extremes and 40 sample seeds, with documented problem seeds, are in [evidence/scene-05](evidence/scene-05/README.md). Structure only: no painting, and not a visual-gate candidate. The user's review ("some hills and some scrub"; the goal is awe and sweeping vistas) led to 05b (2026-09-26). It added the `tower-peak` and `high-vantage` templates, clouds, a structural light pool, trees as scale cues and awe metrics, plus an Awe criterion in the rubric and [rating rounds](visual-review/) to calibrate the metrics against the user's scores. 05b blocks task 06. 06 (2026-09-27): [painting](painting.md). `PaintRenderer` has authored palettes, six plant species, a mixed forest, washes and gouache, loose edges, paper and granulation. Visual-review rounds 2–5 accepted the direction ("All the images look GREAT"), which is not the task 08 gate. Coverage uses an exact row-bin edge index: on real scenes the 1920 px preview takes 2.7 ms on the RTX 4070 Ti and 40 ms on an Intel iGPU (previously 441 ms). The compositing model is `pigment_core::composite`, and the GPU matches it to 7.6e-8. Wash/gouache, paper grain and granulation had almost no visible effect at their ends and were strengthened, with the defaults kept byte-identical ([evidence](evidence/paint-06/README.md)). 07 (2026-09-27): [woodland, rocks and water](painting.md#woodland-rocks-and-water-task-07). The scene now carries its light side, and crowns were previously lit from the left in every scene. Greenery varies in size and height: stand ages, stand shadows, emergent trees, emergent and young crowns in silhouettes. Rocks have stronger planes plus lit rims, dark edges and contact shadows. Water has shoreline-mirrored reflections and rock reflections. Each layer picks its coverage ray axis, which keeps the 1920 px preview at 63 ms on the Intel iGPU (2.6 ms on the RTX 4070 Ti). Review: [round 6](visual-review/round-06/README.md); evidence: [paint-07](evidence/paint-07/README.md). **08 (2026-09-27): visual gate passed.** Asked whether they approved the look as the multi-seed prototype, the user said "Yes everything looks fabulous!" ([result](visual-review/round-06/RESULT.md)). Moss that follows the form and clumped shrubland were applied as revision notes. Wind and current on water, and more complex rock surfaces, are recorded for the final rendering. Generator and renderer are now v1, and the baseline (corpus in three aspects plus the round 6 scenes, with recipes and image hashes) is in [visual-review/baseline-08](visual-review/baseline-08/README.md). 09 (2026-09-27): [PNG export](export.md). The new `pigment-io` crate streams tiles into an 8-bit sRGB PNG with no metadata beyond `IHDR`/`sRGB`/`IDAT`/`IEND`, and renames it into place only when complete (cancel or error deletes the temporary file and keeps the old one). Out-of-memory errors retry with half the GPU budget. Exports must match the scene's aspect ratio exactly; 4K/8K presets pick the largest exact-ratio frame. On the RTX 4070 Ti, 8K takes 272 ms and 16384×9216 takes 939 ms. Host memory peaks at one band above the baseline, and per-process GPU memory stays at 200 MiB at every size. Four tilings and orders gave byte-identical 8K files, and 1:1 crops at tile corners show no seams ([evidence](evidence/export-09/README.md)). 10 (2026-09-27): [recipe files](recipe-files.md). `read_recipe` limits the size before reading and requires UTF-8 before the strict loader; `write_recipe` validates and replaces atomically. `Document` holds the prose in memory, with keep-source-text off by default, a path and a dirty flag, and replaces itself only from a valid file. Errors carry no contents, prose or path. All 47 baseline recipes re-save byte-identically, regenerate their frozen checksums and, after save and reopen, repaint to the approved image hashes. A recipe saved in one process reproduces in another. A source-free recipe holds no trace of the words. A digest is not encryption: guessable prose can be confirmed against it. 11 (2026-09-27): [desktop studio](studio.md). `pigment-studio` is an eframe/egui 0.36 window sharing the painter's device, with the render worker on the latest-wins mailbox, scene reuse, 300/100 ms debounce, exact-aspect previews up to 1920 px, diagnostics, and init-failure and device-loss screens. The scripted run on the RTX 4070 Ti types, resizes, rejects a deliberately out-of-order result and closes mid-render; with a simulated 1.5 s render the longest UI frame gap was 21 ms. Undelayed previews reach the UI 22–30 ms after the request, and a 1000-request storm stays at one running and one pending job with +2.4 to +4.6 MiB memory. The AT-SPI tree shows named controls. An iGPU that cannot present to the display is a known limitation with a follow-up task. The visual design pass moves to task 12 by the user's choice. 12 (2026-09-28): [studio controls, compositions and recipes](studio.md). Sliders are generated from `settings::CONTROLS` in Structure, Paint handling and Appearance groups (Advanced collapsed), with value text, a default notch, Reset and full keyboard control. Another Composition and Previous change only the variation. Open, Save and Save As use native dialogs on a helper thread, and replacing or closing unsaved work asks first; source-free recipes open without invented prose. Slider drags render 960 px interaction previews, then a settled preview whose cap rose to 3840 px (8.9 ms at 3840×2160). Headless egui_kittest tests drive the window from the keyboard and check every control's invalidation, including unchanged geometry checksums for paint-only changes. The real-window script drags Form and Edge Looseness every frame, and the paint drag rebuilds no scene. Following an Impeccable interview, PRODUCT.md records the product; the user chose the graphite working console direction, recorded in DESIGN.md. Evidence: [studio-12](evidence/studio-12/README.md).

## Control boundaries

- **Form** controls the structural scene: ridge massing, lake/shore shape, terrain planes and vegetation placement/density. Composition variation is a separate seeded layout control; users can explore it without editing prose.
- **Paint Handling** controls mark scale, wash transparency, pigment granulation, soft/hard edge selection and gouache accents. These controls should not change scene geometry. Independent random streams prevent paint tweaks from perturbing terrain or trees.
- **Palette and atmosphere** alter color, lighting/haze and depth appearance while preserving geography, shoreline, ridge silhouette and vegetation positions. Verify with structural snapshots before/after; visual overlap alone is not a sufficient test.
- Seasons and biome selectors are **later** controls, not part of the initial first-scene prototype. Only implement controls within their designated tasks; don't add UI affordances for unimplemented behaviors.

## Non-goals and constraints

No semantic prompting, training or inclusion of reference art; no mandatory cloud, watermark or attribution; no navigable 3D world, animals or buildings in the first scene. No promise of CPU-only MVP operation, chosen GPU/UI stack, exact cross-hardware pixels, bundled-art rights, or Windows/macOS support before real validation. A local Git repository is not a GitHub publication. Ship only audited assets/dependencies and omit original prose from exported image metadata by default.
